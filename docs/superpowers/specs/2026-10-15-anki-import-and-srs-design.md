# Design Specification: Anki (.apkg) Import & Spaced Repetition System (SRS) for Quenti

**Date:** 2026-10-15  
**Topic:** Anki Package Import, Deck Hierarchy, Media Extraction, and SM-2 Spaced Repetition Study Mode  
**Status:** In Review  

---

## 1. Executive Summary

Quenti is an open-source Quizlet alternative built on Next.js, tRPC, Prisma, and Chakra UI. This design introduces full Anki package (`.apkg`) support and an authentic Anki Spaced Repetition (SRS) study mode.

The feature enables users to import `.apkg` files (supporting both modern Anki 2.1+ zstd/protobuf packages like `All Decks.apkg` and legacy Anki 2.0 packages), extract and serve media (images and audio), preserve hierarchical decks as Quenti Folders and StudySets, and study cards with the classic 4-button Anki SM-2 scheduler (`Again`, `Hard`, `Good`, `Easy`).

## 2. Architecture & Data Model

### 2.1 Prisma Schema Additions

To support Anki Spaced Repetition scheduling alongside existing Quenti study modes without breaking legacy functionality, we introduce a dedicated `AnkiCardSchedule` model linked to `Term` and `User`.

```prisma
enum AnkiCardQueue {
  New        // 0: Unseen / new card
  Learning   // 1: In learning steps (< 1 day)
  Review     // 2: Standard graduated review card
  DayLearn   // 3: Re-learning card spanning across days
  Suspended  // -1: Suspended
}

model AnkiCardSchedule {
  id             String        @id @default(cuid())
  userId         String
  termId         String
  studySetId     String
  queue          AnkiCardQueue @default(New)
  step           Int           @default(0)     // Index in learning steps
  interval       Int           @default(0)     // Interval in days (or 0 if intraday learning)
  easeFactor     Int           @default(2500)  // Ease factor in tenths of percent (2500 = 250%)
  reps           Int           @default(0)     // Number of completed reviews
  lapses         Int           @default(0)     // Number of times card failed
  due            DateTime      @default(now()) // When next due for review
  lastReviewedAt DateTime?
  createdAt      DateTime      @default(now())
  updatedAt      DateTime      @updatedAt

  user     User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  term     Term     @relation(fields: [termId], references: [id], onDelete: Cascade)
  studySet StudySet @relation(fields: [studySetId], references: [id], onDelete: Cascade)

  @@unique([userId, termId])
  @@index([userId, studySetId, due, queue])
}
```

### 2.2 Term & Deck Mapping

An Anki note type can generate one or multiple cards based on its templates.
- **Deck hierarchy**: Anki decks use `::` separation (e.g. `4000 Essential English Words::1.Book`).
  - The root deck name `4000 Essential English Words` is created as a Quenti `Folder`.
  - Sub-decks (e.g. `1.Book`, `2.Book`) are created as Quenti `StudySet`s and assigned to the parent `Folder` via `StudySetsOnFolders`.
  - Single standalone decks without `::` are created directly as `StudySet`s.
- **Card content mapping**:
  - For each card generated by an Anki note:
    - Front question rendered via template -> `Term.word` (plain text fallback) + rich HTML / audio / image tags.
    - Back answer rendered via template -> `Term.definition` + rich HTML / audio / image tags.
    - Media attachments (e.g., `<img src="...">` and `[sound:...]`) are extracted and referenced via local media endpoints.
    - Order is preserved in `Term.rank`.

## 3. Anki Package (.apkg) Parser

### 3.1 Dual-Format Support

Anki `.apkg` files are standard zip archives. The parser supports both format variants:

1. **Modern Format (Anki 2.1.20+)**:
   - `collection.anki21b`: Primary SQLite database compressed with **Zstandard (zstd)**.
   - Custom SQLite collation `unicase`: registered dynamically in the SQLite connection.
   - Tables: `decks`, `notetypes`, `fields`, `templates`, `notes`, `cards`, `revlog`.
   - `media`: Compressed or uncompressed Protobuf dictionary mapping numeric entry IDs in the ZIP to original media filenames (e.g., entry `8212` -> `11_0811.jpg`).
2. **Legacy Format (Anki 2.0 / early 2.1)**:
   - `collection.anki2`: Uncompressed SQLite database.
   - `col` table: JSON columns `models` (templates/fields) and `decks`.
   - `media`: JSON map string mapping numeric entry IDs to filenames (`{"0": "image.png"}`).

### 3.2 Media Asset Extraction & Serving

- Extracted media files (audio files `.mp3`, `.wav`, images `.jpg`, `.png`, `.gif`, `.svg`) are stored under `public/uploads/anki/[setId]/` or streamed via `/api/anki/media/[setId]/[filename]`.
- HTML tags in rendered card templates are sanitized and updated:
  - `<img src="xyz.jpg">` -> `<img src="/api/anki/media/[setId]/xyz.jpg" class="anki-img" />`
  - `[sound:xyz.mp3]` -> custom interactive audio player component `<audio controls src="/api/anki/media/[setId]/xyz.mp3">` with keyboard shortcut `R` to replay.

### 3.3 Template & Cloze Engine

- Field replacement: `{{FieldName}}` replaced with the note's field content.
- Conditional replacement: `{{#Field}}...{{/Field}}` and inverted `{{^Field}}...{{/Field}}`.
- Special tags: `{{FrontSide}}` on back templates is replaced with the rendered front content without answer fields.
- Cloze deletion: `{{cloze:FieldName}}`:
  - Front: `{{c1::answer::hint}}` -> `[...]` or `[hint]`.
  - Back: `{{c1::answer::hint}}` -> `<span class="anki-cloze">answer</span>`.

## 4. Spaced Repetition (SRS) Engine

### 4.1 SM-2 Scheduling Algorithm

Cards transition through states based on user ratings:
- **Rating 1: Again (Fail)**
  - Resets to learning step 0 (`step = 0`, `queue = Learning`).
  - Next interval: 1 minute (intraday review).
  - Increments `lapses += 1`, decreases `easeFactor = max(1300, easeFactor - 200)`.
- **Rating 2: Hard**
  - If in learning: repeat current step or interval = 1.2 * step.
  - If in review: interval = `max(lastInterval + 1, round(lastInterval * 1.2))`.
  - Decreases `easeFactor = max(1300, easeFactor - 150)`.
- **Rating 3: Good**
  - If in learning step 0 (1m) -> advances to step 1 (10m).
  - If in final learning step -> graduates to Review (`queue = Review`, interval = 1 day, `due = now + 1 day`).
  - If in review -> interval = `round(lastInterval * (easeFactor / 1000))`, `due = now + interval days`.
- **Rating 4: Easy**
  - Immediately graduates to Review (`queue = Review`).
  - Interval = `max(4, round(lastInterval * (easeFactor / 1000) * 1.3))`.
  - Increases `easeFactor = easeFactor + 150`.

### 4.2 Queue & Review Session Builder

- Review queries retrieve cards in order:
  1. `Learning` / `DayLearn` cards whose `due <= now()`
  2. `Review` cards whose `due <= now()`
  3. `New` cards (up to daily set limit)
- Real-time count badges displayed on study dashboard:
  - Blue: New cards
  - Red: Learning / Re-learning cards
  - Green: Due review cards

## 5. User Interface & Experience

1. **Import Modal (`apps/next/src/components/import-from-anki-modal.tsx`)**:
   - Integrated into Set and Folder creation menus alongside "Import from Quizlet".
   - Supports drag-and-drop file upload with progress indicator.
2. **CLI Bulk Importer (`scripts/import-anki.ts`)**:
   - High-performance streaming importer for large archives like `All Decks.apkg` (212MB, 3,873 cards, 14,900+ media assets).
3. **Anki SRS Study Page (`apps/next/src/pages/[id]/anki.tsx`)**:
   - Card Display:
     - Clear typographic styling matching Anki night/day themes.
     - Auto-playing and hotkey-replayable audio.
     - Responsive image scaling.
   - Controls:
     - Space / Enter: Flip card to show answer.
     - Number keys `1`, `2`, `3`, `4`: Select rating.
     - Button bar showing estimated next intervals on each button (e.g. `<10m`, `1d`, `4d`).
   - Summary screen on completion with count of reviewed cards and upcoming due cards.
